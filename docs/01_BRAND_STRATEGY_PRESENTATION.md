## สไลด์ที่ 2 — สรุปผู้บริหาร (Executive Summary)

**หัวข้อหลัก:** ทำไมต้อง beNeCare ในปีนี้และปีหน้า  
**หัวข้อย่อย:**
- ปีนี้ได้งานประกันกลุ่มไซส์ใหญ่หลายองค์กร พนักงานรวมหลักหมื่นคน
- ปัจจุบันยังดูแลแบบไม่มีระบบ รับได้ แต่มองระยะยาวแล้วเสี่ยงต่อการตกหล่น
- ปีหน้าต้องมีระบบดูแลลูกค้าประกันกลุ่ม ผ่าน LINE OA ตอบคำถามตลอด 24 ชั่วโมง
- แยกข้อมูลแต่ละบริษัท รองรับสูงสุด 5,000 คนต่อบริษัท ส่วนใหญ่หลัก 100–1,000 คน
- เริ่มติดตั้งระบบช่วงต้นปี พร้อมเชื่อมกับระบบของ AIA

**คำบรรยาย:**  
ปีนี้เราได้ลูกค้าประกันกลุ่มไซส์ใหญ่หลายแห่ง รวมพนักงานหลักหมื่นคน การดูแลแบบ manual ยังพอรับไหว แต่ปีหน้าถ้าขยายต่อเราต้องมีระบบที่รองรับความซับซ้อน beNeCare คือคำตอบ — ระบบตอบคำถาม 24 ชั่วโมงผ่าน LINE OA แยกเป็นบริษัทได้ ปลอดภัย และเตรียมพร้อมเชื่อมต่อ AIA

## สไลด์ที่ 3 — ที่มาของชื่อและความหมาย (Brand Name & Meaning)

**หัวข้อหลัก:** beNeCare — จำง่าย ดูแลได้อย่างเต็มประสิทธิภาพ  
**หัวข้อย่อย:**
- **beNe** = Benevolent / Benefit (เจตนาดี, ประโยชน์, สวัสดิการ)
- **Care** = การดูแล เอาใจใส่ ต่อเนื่อง
- ออกเสียงคล้ายคำว่า "bene care" → ฟังแล้วให้ความรู้สึกเป็นมิตร ใช้งานจริงได้ทันที
- เขียนภาษาอังกฤษจำง่าย ขึ้นโฆษณา ขึ้นสไลด์ ขึ้นโลโก้ได้ดี
- ต่อท้ายด้วย "by AIA Partner" ได้เมื่อได้รับอนุญาตจาก AIA แล้ว

**คำบรรยาย:**  
ชื่อ beNeCare ตั้งใจให้จำง่าย พูดแล้วติดหู ไม่ยากสำหรับคนไทยและคนต่างชาติ แยกคำออกเป็น beNe (จาก Benevolent หรือ Benefit แปลว่า เจตนาดี / ประโยชน์) บวก Care (การดูแล) รวมกันคือการดูแลด้วยเจตนาดี ซึ่งตรงกับแกนหลักของงานประกันกลุ่ม คือการดูแลพนักงานทุกคนในองค์กรอย่างทั่วถึง

## สไลด์ที่ 4 — ทิศทางแบรนด์ (Brand Direction)

**หัวข้อหลัก:** Lifestyle + Formal + Premium + Human Care  
**หัวข้อย่อย (แยกเป็น 4 เสา):**

| เสาหลัก | ความหมายในระบบ beNeCare |
|---|---|
| **Lifestyle** | ใช้ผ่าน LINE OA เครื่องมือที่คนใช้ทุกวัน ตอบคำถามเรื่องประกันได้เหมือนคุยกับเพื่อน ไม่ต้องติดตั้งแอปเพิ่ม |
| **Formal** | ระบบหลังบ้าน Admin ERP แบบทางการ สำหรับ HR และผู้ดูแลองค์กร จัดการพนักงาน รายงาน อนุมัติ อย่างมีโครงสร้าง |
| **Premium** | ภาพลักษณ์หรูหรา ทันสมัย ใช้สีและดีไซน์ใกล้เคียง AIA ให้ความรู้สึกว่าเป็นบริการระดับพรีเมียมสำหรับองค์กรใหญ่ |
| **Human Care** | แชตบอตตอบคำถามเบื้องต้น แต่เมื่อเป็นเรื่องซับซ้อน ส่งต่อให้เจ้าหน้าที่คนจริงดูแล (Human Handoff) ไม่ทิ้งให้ลูกค้าคุยกับบอตเพียงลำพัง |

**คำบรรยาย:**  
แบรนด์ beNeCare ไม่ได้เน้นแค่เทคโนโลยี แต่เน้นการดูแลคนเป็นหัวใจ ลูกค้าผ่าน LINE OA ได้ประสบการณ์สบาย ๆ เหมือนคุยไลน์ปกติ (Lifestyle) ส่วน HR ใช้ระบบหลังบ้านแบบ formal จริงจัง ดีไซน์ออกมาพรีเมียมสมกับที่เป็นพาร์ทเนอร์ AIA และทุกครั้งที่ระบบตอบไม่ได้ มีมนุษย์เข้ามาดูแลต่อเสมอ (Human Care)

## สไลด์ที่ 5 — เอกลักษณ์ภาพลักษณ์และโทนสี (Visual Identity)

**หัวข้อหลัก:** ปรับโทนสีใกล้เคียง AIA  UX/UI แบบ mng-erp (Management ERP)  
**หัวข้อรอง:**

**สีหลัก (Primary — ใกล้เคียง AIA):**
- **AIA Red** — เฉดสีแดงหลักของแบรนด์ AIA (ต้องยืนยันเฉดสีจริงกับทีมแบรนด์ AIA ก่อนใช้งานจริง) ตัวอย่าง `#E11D48` หรือใกล้เคียง
- ใช้กับโลโก้ beNeCare, ปุ่มหลัก, หัวข้อสำคัญ

**สีรอง (Secondary — Formal & Premium):**
- Navy / Slate `#0F172A` — ให้ความรู้สึกทางการ น่าเชื่อถือ เหมาะระบบ ERP หลังบ้าน
- Warm White `#F8FAFC` — พื้นหลังนุ่มนวล เป็นมิตร (Lifestyle & Human Care)
- Amber/Gold `#F59E0B` — สีเสริมระดับพรีเมียม ใช้กับจุดเด่น เช่น ป้ายแจ้งเตือนพิเศษ, ไอคอนระดับ VIP

**ตัวอักษร (Typography):**
- หัวเรื่อง: ฟอนต์ตัวหนา อ่านง่าย รองรับภาษาไทยและอังกฤษ
- เนื้อหา: ฟอนต์สะอาด โมเดิร์น รองรับการอ่านบนมือถือผ่าน LINE OA Rich Menu

**โทนการสื่อสาร (Tone of Voice):**
- เป็นมิตร ให้ความรู้ กระชับ สุภาพ ใช้ภาษาไทยที่เข้าใจง่าย ไม่ใช้ศัพท์ประกันที่ยากเกินไป

**คำบรรยาย:**  
UX/UI ของเราจะออกแบบในรูปแบบ Management ERP — หน้าหลังบ้านสำหรับผู้ดูแลระบบต้องดูเป็นทางการ น่าเชื่อถือ ใช้สีน้ำเงินเข้มเข้มข้น ส่วนจุดเด่นใช้แดง AIA เพื่อเชื่อมโยงกับแบรนด์ AIA ทั้งหมดนี้ต้องยืนยันเฉดสีและโลโก้กับทีมแบรนด์ AIA ก่อนผลิตจริง (อยู่ในส่วน "ต้องยืนยันกับ AIA" ไม่ใช่ส่วนที่ AI สร้างเอง)

## สไลด์ที่ 6 — กลุ่มเป้าหมาย (Target Audience)

**หัวข้อหลัก:** ใครใช้ beNeCare บ้าง  
**หัวข้อรอง:**

**1. ผู้บริหารและฝ่ายบุคคล (HR / Admin ขององค์กรลูกค้า):**
- องค์กรขนาดใหญ่ (พนักงานสูงสุด 5,000 คนต่อบริษัท) และกลุ่มกลาง (100–1,000 คน)
- ต้องการดูแลสวัสดิการประกันกลุ่มของพนักงานอย่างเป็นระบบ
- ต้องการรายงาน สถิติ การแจ้งเตือน เป็นภาษาไทย

**2. พนักงานในองค์กร (End Users / ผู้เอาประกัน):**
- ใช้ LINE OA ถามคำถามเกี่ยวกับประกันกลุ่ม เช่น เคลมอย่างไร คุ้มครองอะไรบ้าง ต่ออายุเมื่อไร
- ต้องการคำตอบเร็ว ตลอด 24 ชั่วโมง

**3. ทีมดูแลลูกค้าของเรา (beNeCare Operations Team):**
- ดูแลหลายบริษัทพร้อมกัน แยกข้อมูลไม่ให้ปนกัน
- ต้องมีเครื่องมือส่งข้อความหาแต่ละบริษัท (Broadcast) และดูสถิติการใช้งาน

**คำบรรยาย:**  
กลุ่มเป้าหมายหลักมีสามฝ่าย HR ต้องการระบบหลังบ้านจัดการพนักงานได้เป็นบริษัท พนักงานต้องการถามประกันผ่านไลน์ได้ตลอดเวลา และทีมดูแลลูกค้าของเราต้องจัดการหลายบริษัทพร้อมกันโดยข้อมูลไม่ปนเปกัน beNeCare ออกแบบรองรับทั้งสามฝ่ายนี้

## สไลด์ที่ 7 — บริการหลักของระบบ (Core Services)

**หัวข้อหลัก:** beNeCare ทำอะไรได้บ้าง  
**หัวข้อรอง:**

| บริการ | รายละเอียด | ช่องทาง |
|---|---|---|
| **ถาม-ตอบประกันกลุ่ม 24 ชม.** | AI ตอบคำถามเบื้องต้น เรื่องความคุ้มครอง การเคลม เอกสารที่ต้องใช้ | LINE OA Chatbot |
| **คู่มือการเคลม step-by-step** | แนะนำขั้นตอนเคลมประกันกลุ่ม แนบไฟล์ คำแนะนำเบื้องต้น | LINE OA / Rich Menu |
| **แจ้งเตือนสำคัญ** | เตือนต่ออายุกรมธรรม์, วันหยุดสำนักงาน, ข่าวสารจาก AIA | LINE Broadcast |
| **จัดการพนักงานและสวัสดิการ** | เพิ่ม/แก้ไข/ลบพนักงาน, ดูสถานะความคุ้มครอง, รายงาน | Admin Web (ERP) |
| **ระบบติดตั้งครั้งแรกและอัปเกรด** | ตั้งค่า DB, สร้างแอดมิน, ตั้งค่า LINE OA, อัปเกรดระบบในอนาคต | Installer + Settings |
| **ส่งต่อเจ้าหน้าที่คนจริง** | เมื่อ AI ตอบไม่ได้ หรือลูกค้าต้องการคุยกับคน | Human Handoff (Admin/chat) |

**คำบรรยาย:**  
บริการหลักแบ่งเป็นสองฝั่ง ฝั่งพนักงานใช้ LINE OA เป็นหลัก ถามได้ตลอด 24 ชั่วโมง มีคู่มือเคลม มีการแจ้งเตือน ส่วนฝั่งองค์กรใช้หน้า Admin แบบ ERP จัดการพนักงาน ดูรายงาน และติดตั้ง/อัปเกรดระบบได้เองในส่วนการตั้งค่า

## สไลด์ที่ 8 — การเชื่อมต่อกับ AIA (AIA Integration)

**หัวข้อหลัก:** พร้อมเชื่อมต่อกับระบบของ AIA  
**หัวข้อรอง:**

**สิ่งที่วางแผนไว้ (ยังต้องยืนยันกับ AIA):**
- เชื่อมต่อ API ของ AIA สำหรับตรวจสอบกรมธรรม์, สถานะเคลม, เบี้ยประกัน
- ใช้โลโก้และชื่อ AIA ในสื่อประชาสัมพันธ์และหน้าเข้าสู่ระบบ
- SSO / Single Sign-on กับระบบของ AIA (ถ้ามี)
- ดึงข้อมูลพนักงานผู้เอาประกันจากระบบ AIA มาใช้ใน beNeCare

**ข้อสำคัญ:** รายการด้านบนยัง **ไม่ได้รับการยืนยันจาก AIA** จึงจัดอยู่ในส่วน "ต้องยืนยันกับ AIA" ไม่ใช่ข้อกำหนดที่ให้ AI สร้างระบบขึ้นมาเอง

**คำบรรยาย:**  
beNeCare ออกแบบมาให้เชื่อมต่อกับ AIA ได้ในอนาคต แต่ทั้งหมดยังเป็นแผนเบื้องต้น ต้องไปยืนยันกับทีม AIA อีกครั้งก่อน จึงห้ามให้นักพัฒนาหรือ AI สร้างฟังก์ชันเชื่อมต่อ AIA ขึ้นมาเองโดยเด็ดขาด จนกว่าจะมีเอกสารยืนยันจาก AIA เป็นลายลักษณ์อักษร

## สไลด์ที่ 9 — โรดแมปการพัฒนา (Roadmap)

**หัวข้อหลัก:** แผนการพัฒนา beNeCare ช่วงต้นปีและต่อเนื่อง  
**หัวข้อรอง:**

| เฟส | ระยะเวลา | เป้าหมายหลัก |
|---|---|---|
| **Phase 1 — Foundation** | เดือนที่ 1–2 | ติดตั้งระบบครั้งแรก (Installer), MariaDB, multi-tenant พื้นฐาน, LINE OA ตอบคำถามพื้นฐาน, Admin จัดการบริษัทและพนักงาน |
| **Phase 2 — AI & Automation** | เดือนที่ 3–4 | เพิ่ม AI ตอบคำถาม, Intent Classification, Rich Menu, แจ้งเตือนผ่าน LINE Broadcast |
| **Phase 3 — Human Care & Operations** | เดือนที่ 5–6 | ระบบส่งต่อเจ้าหน้าที่คนจริง, ดูสถิติการใช้งานแยกบริษัท, รายงานสำหรับผู้บริหาร |
| **Phase 4 — AIA Integration & Scale** | เดือนที่ 7 ขึ้นไป (หลังยืนยันกับ AIA) | เชื่อมต่อ API กับ AIA, รองรับบริษัทขนาดใหญ่สูงสุด 5,000 คน, อัปเกรดระบบผ่านส่วนการตั้งค่า |

**คำบรรยาย:**  
โรดแมปแบ่งเป็นสี่เฟส เริ่มจากติดตั้งระบบพื้นฐานและ LINE OA ตอบคำถามเบื้องต้น ต่อด้วย AI ช่วยตอบคำถาม จากนั้นเพิ่มคนจริงเข้ามาดูแลเมื่อจำเป็น และเฟสสุดท้ายคือเชื่อมต่อกับ AIA หลังจากได้รับการยืนยันแล้ว รวมทั้งมีระบบอัปเกรดในส่วนการตั้งค่าเพื่อให้ระบบใช้งานได้ยาวนานในอนาคต

## สไลด์ที่ 10 — ตัววัดความสำเร็จ (KPIs / Success Metrics)

**หัวข้อหลัก:** วัดผลอย่างไรว่า beNeCare สำเร็จ  
**หัวข้อรอง:**
- เวลาตอบคำถามเฉลี่ยผ่าน LINE OA (เป้าหมาย ตอบทันทีโดย AI, คำถามซับซ้อนส่งต่อมนุษย์ภายในกี่นาที)
- ร้อยละคำถามที่ AI ตอบได้ถูกต้องโดยไม่ต้องส่งต่อคน
- จำนวนบริษัทและพนักงานที่ใช้งานระบบ (เป้าหมายปีแรก: องค์กรหลักหมื่นพนักงาน)
- คะแนนความพึงพอใจของ HR และพนักงาน
- เวลาหยุดทำงานของระบบ (Uptime เป้าหมาย 99.9%)

**คำบรรยาย:**  
เราจะวัดผลจากความเร็วในการตอบคำถาม ความแม่นยำของ AI จำนวนบริษัทและพนักงานที่ใช้งาน ความพึงพอใจ และเสถียรภาพของระบบ ตัวเลขเหล่านี้จะบอกเราว่า beNeCare ช่วยดูแลลูกค้าได้อย่างเต็มประสิทธิภาพหรือไม่

## สไลด์ที่ 11 — สรุปและขั้นตอนต่อไป (Next Steps)

**หัวข้อหลัก:** อะไรที่ต้องทำทันที  
**หัวข้อรอง:**
1. ยืนยันชื่อ beNeCare และโลโก้กับทีมแบรนด์ (รวมถึงขออนุญาตใช้ชื่อ/โลโก้ AIA)
2. ยืนยันขอบเขตการเชื่อมต่อ API กับ AIA (สิ่งที่ยังต้องยืนยัน)
3. ติดตั้งระบบครั้งแรกด้วย Installer (Next.js + MariaDB)
4. เตรียม LINE OA Official Account และเชื่อมต่อ Messaging API
5. ส่งมอบเอกสาร AI System Development Brief ให้ทีมพัฒนาสร้างระบบต่อไป

**คำบรรยาย:**  
ขั้นตอนต่อไปคือการยืนยันชื่อแบรนด์และสิทธิการใช้โลโก้ AIA ยืนยันขอบเขต API กับ AIA จากนั้นติดตั้งระบบเบื้องต้น เตรียม LINE OA และส่งมอบเอกสารคำสั่งพัฒนาระบบ (AI System Development Brief) ให้ทีมสร้างระบบต่อไปครับ
